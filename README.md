# fact-corpus-pipeline

![selfcheck](https://github.com/Osmosy/fact-corpus-pipeline/actions/workflows/ci.yml/badge.svg)

Конвейер аналитики корпуса: колоды и отчёты → машиночитаемые факты → анализ несколькими
моделями → сравнение → решения → проверяемые выводы.

Не «прогнать LLM по документам», а получить после прогона конкретику: какие факты модели взяли
в опору, на чём сошлись, что не взял никто, и каких признанных обязательств в выводах нет.

## Зачем

Обычная работа с корпусом даёт текст, который «выглядит полным». Здесь полнота — число:
на корпусе из 7 колод (260 страниц, 653 факта) конвейер показал, что две модели согласились
на 140 фактах из 653, 105 фактов взяла ровно одна, 43 не взял никто — и из этих 43 только
девять были настоящими потерями, остальные 28 фоном. Выводы покрывали 19 из 38 признанных
обязательств. Это и есть ответ на вопрос «полные ли выводы». Подробный разбор с числами,
решениями и честным списком того, чего кейс не доказывает — `docs/case-study.md`.

## Что внутри

| файл | шаг |
|---|---|
| `scripts/build_facts.py` | `page_facts.json` → канон `facts.jsonl` (id из содержимого) |
| `scripts/run_analysis.py` | прогон модели по фактам колоды со строгим контрактом ответа |
| `scripts/compare_analyses.py` | четыре среза выбора + кластеры выводов |
| `scripts/summary_all.py` | картина по корпусу: что взято, что не взял никто |
| `scripts/blind_spots.py` | слепые зоны и второй проход по ним |
| `scripts/apply_fact_decisions.py` | план решений → `fact_decisions.json` + `dispositions.json` |
| `scripts/build_appendix.py` | приложение «Справочно» — единственный генератор |
| `scripts/apply_dispositions.py` | применяет решения к реестру обязательств |
| `scripts/rb_to_info.py` | панель второстепенного рынка → справочно |
| `scripts/run_all.sh` | все колоды × все каналы |
| `SKILL.md` | тот же маршрут как навык агента: этапы, проверки качества материала, грабли |

## Как это работает

1. **Качество входа.** Число обязано дословно стоять на своей странице; подпись факта —
   дословная подстрока строки таблицы; панели (например `### РФ` / `### РБ`) не смешиваются;
   повторы слайдов и обрезанные ячейки ловятся до анализа, а не в выводах.
2. **Канон фактов.** Один факт = одна строка JSON, `fact_id` = sha256 от
   `(колода, страница, подпись, значение)`. Пересборка не сдвигает номера и не плодит дублей.
3. **Анализ.** Модель возвращает `selected` / `conclusions` / `not_relevant`, каждый вывод
   со ссылками на `fact_id`. Прогон принимается, только если все id существуют, выводы есть
   и у каждого вывода есть ссылки.
4. **Сравнение.** Четыре среза: выбрали все, большинство, ровно один, не выбрал никто.
   Выводы кластеризуются по пересечению ссылок и близости текста.
5. **Слепые зоны.** Факты, которые не взял никто, отдаются моделям отдельным вопросом:
   `material` / `background` / `irrelevant` с причиной. Массовый прогон теряет факты на
   внимании, точечный — нет.
6. **Решения.** У факта три судьбы: `conclusions` (обязан быть в выводах), `info` (идёт в
   приложение «Справочно»), `waive` (обязательство снято с причиной).
7. **Проверка.** Реестр обязательств (см. [vector-grace](https://github.com/Osmosy/vector-grace))
   отвечает не «что показалось важным», а «что обязано быть в выводах»: `coverage`, `drift`,
   `replay`.

## Быстрый старт

```bash
git clone https://github.com/Osmosy/fact-corpus-pipeline.git
export SKILL=$PWD/fact-corpus-pipeline/scripts

cd /path/to/project          # здесь decks/ и docs/
CORPUS_ROOT=$PWD python3 $SKILL/build_facts.py
CORPUS_ROOT=$PWD python3 $SKILL/run_analysis.py --backend ollama --deck <колода>
CORPUS_ROOT=$PWD python3 $SKILL/compare_analyses.py <колода>
CORPUS_ROOT=$PWD python3 $SKILL/blind_spots.py --review ollama
CORPUS_ROOT=$PWD python3 $SKILL/blind_spots.py --summary
```

Требуется Python 3.11+ и один из каналов: CLI с промо-пулом (по умолчанию
`~/.local/bin/zcode-start-plan`) или любой OpenAI-совместимый эндпоинт на
`http://127.0.0.1:11434/v1/chat/completions` (правится в `run_analysis.py`).

Переменные окружения:

| переменная | смысл |
|---|---|
| `CORPUS_ROOT` | корень проекта с данными (по умолчанию текущий каталог) |
| `APPENDIX_INFO` | путь к приложению «Справочно» (по умолчанию единственное `reviews/*/APPENDIX-INFO.md`) |
| `GRACE_REGISTRY` | путь к установленному реестру `vector-grace/registry` |
| `DECKS`, `BACKENDS` | список колод и каналов для `run_all.sh` |

## Форматы данных

Факт (`docs/facts/facts.jsonl`):

```json
{"fact_id": "F-1a2b3c4d5e6f", "deck": "inkofood-2026", "page": 34,
 "label": "Дата производства и срок годности на лицевой стороне упаковки",
 "value": "61,7 %", "thematic": true, "deck_sha256": "…"}
```

Ответ модели (`docs/facts/runs/<колода>.<backend>-<штамп>.json`):

```json
{"selected":    [{"fact_id": "F-…", "why": "чем важен"}],
 "conclusions": [{"text": "вывод", "fact_ids": ["F-…"]}],
 "not_relevant":[{"fact_id": "F-…", "why": "почему не значим"}]}
```

План решений (`docs/facts/plan.json`) и решения (`docs/facts/fact_decisions.json`) лежат в
проекте, а не в скриптах: решения меняются по ходу разбора.

## Что здесь не лежит

- **Данные корпуса** — колоды, факты и прогоны остаются в проекте-потребителе.
- **Движок реестра** — спаны, байтовые хэши, гейты дрейфа и перезапуск чекеров живут в
  `vector-grace/registry`. Здесь только скрипты, которые его вызывают.
- **Конкретные модели** — каналы подключаются, а не зашиты: подойдёт любой, кто отдаёт
  строгий JSON.

## Грабли, которые здесь уже оплачены

Правка чекера после регистрации инвалидирует его доказательства; зашитый корень проекта
убивает переносимость; пересборка решений теряет требования-двойники с одинаковым текстом;
два генератора одного документа расходятся по версиям; второстепенный рынок подменяет числа
целевого. Полный список — в `SKILL.md`, раздел «Common Pitfalls», каждый пункт с исправлением.

## Проверки

CI работает в GitHub Actions: матрица Python 3.11–3.13, прогон `ci/selfcheck.py` на каждый
пуш и пул-реквест.

Самопроверка ловит то, что не ловят тесты: не компилирующийся скрипт, сломанный
`run_all.sh`, ссылку README на отсутствующий файл, невалидный frontmatter навыка,
похожее на секрет содержимое.

```bash
python3 ci/selfcheck.py    # локально: 0 — чисто, 1 — список находок
```

Дополнительно в клоне можно включить хук перед пушем, чтобы не отправлять заведомо красное
состояние: `git config core.hooksPath ci/hooks`.
