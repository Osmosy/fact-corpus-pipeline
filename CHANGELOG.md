# Изменения

## 2.4.5 — уточнения после сверки сводки

- **Сводка не противоречит себе**: счёт размеченных чисел убран (он растёт с каждой правкой),
  в подвале указано, что числа и коммиты — состояние на `2e9b6c6` (v2.4.3), а сам документ
  лежит в репозитории с версии 2.4.4.
- **Связанные ключи обязаны совпадать**: `owner_exceptions.with_marker` и `.total` сверяются
  между собой. Текст мог остаться согласованным со снимком, а смысл — нет: маркер пропал
  у части исключений, и число в выводах снова читается как число по РФ. Проверено
  отрицательным прогоном: 3 против 4 даёт код 1.
- **Граница проверки названа прямо** — в SKILL и в сводке: снимок копируется вручную, поэтому
  сверяется текст со снимком, а не снимок с корпусом.

## 2.4.4 — сводка аудита в репозитории

- **`docs/audit-2026-11.md`** — сводка семи раундов ревью: итоги, числа до и после с причиной
  каждого сдвига, раунды с коммитами, решения владельца, открытые вопросы с пометкой «чьё»,
  ограничения выводов и где ревью ошибалось.
- **`ci/numbers.py` знает два вида чисел.** Текущие размечены ключами и сверяются со снимком;
  исторические («до правок») помечены `<!-- было -->…<!-- /было -->` и из сверки исключены —
  сравнивать их не с чем. Сводка добавлена в список проверяемых файлов: 173 числа, из них 9
  исторических, расхождений ноль.
- **Кейс §6**: число исключений размечено одним ключом (`decisions.exceptions`), формулировка
  правила уточнена — «без исключений по материальности», ослабить может только владелец через
  `owner_exceptions`.

## 2.4.3 — T-46b

- **Предупреждения — в `stderr`.** Пропущенное исключение, неизвестная панель, словесное
  условие без поля, факт не найден, неоднозначные строки: машинный вывод остаётся чистым,
  тесты разбирают stdout напрямую. Правило записано в SKILL.
- **Подпись пробного прогона.** Было «обязательств на панели „РБ“: 8» — читалось как «всего 8».
  Стало «панель „РБ“: 12, из них в „Справочно“ 8, исключения владельца 4».
- **Тест на подпись** и ключи `owner_exceptions.total` / `with_marker` размечены в кейсе §6.
  Всего тестов 74.

## 2.4.2 — T-46a

- **`owner_exceptions()` читает `require_marker`**: строка или список, приведение к названию
  панели через `panel_aliases` (🇧🇾 → РБ). Неизвестная панель — предупреждение, исключение
  применяется без маркера.
- **Предупреждение про словесное условие**: если в причине написано «только с пометкой», а поля
  `require_marker` нет, навык говорит, что маркер проверяться не будет. Исключение всё равно
  применяется — это подсказка, а не отказ.
- **Видимость**: пробный прогон печатает маркер у каждого исключения, в отчёте ключи
  `owner_exceptions.total` и `owner_exceptions.with_marker`.
- **Шесть тестов**: строка, список, синоним, неизвестная панель, словесное условие без поля,
  независимость маркера от текста причины.

## 2.4.1 — T-46

- **Признак маркера панели — полем, а не текстом.** В `owner_exceptions` появилось
  `require_marker: "РБ"`; предикат версии 6 (`check_fact_in_conclusions_v6.py`) смотрит только
  на это поле. Правка формулировки причины больше не отключает проверку молча. Инварианты
  INV-0160…0163 перевыпущены как INV-0167…0170.
- **Регрессия правила** — `docs/registry/tools/check_marker_rule.py` в проекте: три состояния
  (как есть / причина переписана / причина переписана и маркер убран), ожидание true/true/false.
- **`requirements.rb` переименован**: `requirements.rb_info` — сколько обязательств панели РБ
  в «Справочно», `requirements.rb_total` — сколько их всего. Разные числа, разные ключи.
- Кейс: убрано «REQ-0009, тоже в выводах» — REQ-0008 в «Справочно», рядом стоит только для
  сравнения формулировок. Числа корпуса не менялись: доказано 32, drift 11, replay 275/275.

## 2.4.0 — раунд 7

- **Знание владельца — отдельный тип фактов.** `docs/facts/owner-facts.jsonl`, id `O-<sha12>`,
  дословное утверждение, источник, дата, область. `corpus.load_facts()` по умолчанию его не
  отдаёт: модели не видят этих утверждений ни в промпте, ни в сравнении, ни в слепых зонах.
  Приложение печатает раздел «Знание владельца», отчёт — ключ `owner_facts.total`.
- **Исключения из правила рынка — данными.** `owner_exceptions` с причиной, датой и подписью;
  исключённое требование закрывается выводами, а не остаётся в «Справочно».
- **Предикат версии 5** (`check_fact_in_conclusions_v5.py`): для требования из `owner_exceptions`
  с пометкой в причине pass засчитывается только если в том же предложении стоит маркер панели
  («РБ», «в Беларуси», флаг). Иначе число белорусской панели читается как число по РФ.
- **Раскладки в отчёте**: `decisions.*` (по требованиям, без двойного счёта), `rb_material.total`
  (материалы панели РБ по одному определению), `runs.base/stability/rejected`, `registry.replay_*`.
- **Исправлены числа документов**: «27,6 млн единиц на корпус» убрано (расход по журналу прогонов
  0,85 млн и аккаунтный счётчик пула — разные счёта), REQ-0008 в «было» описан как `conclusions`
  без доказательства, а не «закрывался выводами».

## 2.3.0 — раунд 6

- **Отменено правило REQ-0008** (исключение по материальности не согласовано владельцем).
  `rb_to_info.py` больше не смотрит на вердикты и `consensus`: все требования панели РБ —
  кандидаты в `info`. Исключение возможно только списком `config.json → owner_exceptions`
  (`req_id`, причина, дата, подпись); пустой список — норма, неполное исключение пропускается.
- **`cost_report.py` → поле `scope`**: счётчик пула в кабинете аккаунтный, его нельзя
  сравнивать с расходом корпуса, который считается суммой `usage.pool_units` по `runs/`.
- **`report.py`**: `requirements.rb` считается по панели факта из канона, а не по тексту причины.

## 2.2.0 — раунд 5

- **`stability.py`: позиционный тест на уровне факта** (`position_stats`) — точечно-бисериальная
  корреляция «позиция → выбран» и U-тест Манна — Уитни по каждому повтору, объединение по
  Фишеру, минимально обнаружимый r при мощности 80 %. Вердикт «эффекта нет» всегда идёт с числом
  `mde_r`. Порядок фактов берётся из прогона (`order_ids`), иначе восстанавливается по seed.
- **`run_analysis.py` сохраняет порядок** промпта (`order.order_ids`) — иначе позицию нечем
  проверить: seed есть, а фактический порядок приходилось реконструировать.
- **Имя предиката приведено к версии**: `check_fact_in_conclusions_v4.py` (вместо `_v2.py` при
  `CHECKER_VERSION = "4"`), пути инвариантов и записи доказательств обновлены, replay 266/266.
